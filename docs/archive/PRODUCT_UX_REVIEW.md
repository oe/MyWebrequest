# 普通用户 URL 重定向体验评估

> Historical snapshot, archived 2026-09-09. Statements and results apply only to the original review or candidate; they are not current requirements or release certification. See the [documentation index](../README.md) for maintained guidance.

日期：2026-09-05

实施进展：已增加两网址创建与编辑、精确／整站范围选择、原生域名替换和多个可编辑测试网址。只有两网址仅主机名不同时提供整站替换，限定原协议、主机名和端口，保留路径及参数。简单规则再次打开显示范围与跳转说明；手写规则可借助网址示例生成候选，比较后应用到草稿，再走现有保存流程。新建表单默认启用，用户可关闭后保存为禁用；启用保存复用权限和冲突检查。普通精确匹配不使用正则；包含过滤器特殊字符时回退正则以保持语义。下表保留改动前的评估；路径范围、更多日常模板及普通用户实测仍待后续完成。

产品定位：面向普通用户，核心价值是自己决定网址如何跳转。API 调试、请求头和底层匹配语法属于高级能力。

结论：当前实现有完整的规则管理基础，但第一次成功创建网址跳转的门槛仍然偏高。下一轮应优先改善默认流程，而不是增加更多底层动作。

## 评估范围与证据

官网菜单使用当前本地页面验证。扩展部分基于当前代码检查；浏览器工具的 URL 安全策略禁止打开扩展页面，本轮未对扩展进行视觉或普通用户实测，也没有绕过限制。这份评估不能替代目标用户的可用性测试。

## 普通用户完成一次跳转的路径

| 步骤          | 当前情况                                                                             | 对普通用户的影响                                              | 优先调整                                                     |
| ------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------- | ------------------------------------------------------------ |
| 1. 找到入口   | 官网首屏已改为自定义网址跳转；扩展的“新建规则”仍默认创建拦截规则                     | 核心任务需要先切换动作                                        | 默认入口改为“创建网址跳转”，高级规则另设入口                 |
| 2. 填写网址   | 匹配语法、资源类型排在目标网址之前                                                   | 用户尚未填完两个网址，就需要理解 URL 过滤器、通配符和请求类型 | 简单模式只展示原网址、目标网址、作用范围和结果预览           |
| 3. 测试结果   | 当前测试匹配 URL，不代表地址栏导航会触发；API 示例只匹配 Fetch/XHR，另有限定来源网站 | 用户改完原网址和目标网址后，预览可能匹配，但打开页面不跳转    | 简单模式默认仅处理顶层页面；测试明确说明适用场景和未生效原因 |
| 4. 保存并使用 | 启用、保存和授权是不同状态；已有权限、草稿、冲突与回环保护                           | 安全基础有用，但用户仍需判断规则究竟能否工作                  | 完成时明确呈现“已保存但未启用”“等待网站授权”或“已启用”       |

代码依据：

- [默认规则和 API 示例](../../src/application/rule-service.ts)：`createRule()` 默认 `block`；`redirect-local` 默认 `xmlhttprequest`、`app.example.com` 和 `localhost:3000/v1/$1`。
- [规则编辑器](../../src/ui/rules/rule-editor.tsx)：字段依次包含名称、匹配语法、资源类型、动作，再出现重定向目标。
- [URL 预览](../../src/domain/rules/test-match.ts)：验证规则与 URL 模式，未模拟真实请求的资源类型、来源及其他规则。
- [工具栏弹窗](../../src/ui/surfaces/popup-app.tsx)：当前只保留页面 origin，调用通用的默认拦截规则工厂，无法直接以完整当前网址创建跳转。

## 建议先交付的一轮

1. **提供简单重定向编辑器**：默认“仅此网址”，粘贴原网址和目标网址即可；后台生成规则，不要求输入 `|`、`^`、`*`、`$1`。正则、请求头、资源类型和优先级保留在高级入口。
2. **用日常语言表达作用范围**：“仅此网址”“整个网站”“这个路径下的页面”。替换域名时，明确是否保留后面的路径与查询参数，并实时显示一个完整的转换例子。避免把包含某段文字误当作精确匹配。
3. **换成真实的入门任务**：某个网页转到另一个网页、旧域名转新域名并保留路径、常用链接转到偏好的页面。API → localhost 示例归入高级用法。
4. **打通工具栏捷径**：“让当前网址跳转到…”预填完整页面 URL；以明确按钮完成保存和启用，并在授权不足或规则不适用时给出具体原因。保留一键停用和撤销。

暂缓增加规则市场、云同步或更多请求动作。规则分享可作为后续能力，沿用现有本地导入与变更预览基础，并让分享者主动确认内容。

## 验收标准

- 从空白状态创建“网页 A → 网页 B”，不必接触正则、请求类型或开发者术语。
- 默认只影响用户明确指定的顶层页面，不扩大到站内图片、接口或全部域名。
- 对尾斜杠、查询参数、整站替换与回环给出可理解、可测试的结果。
- 保存后的状态能回答“现在是否生效”；拒绝授权时不显示成功启用。
- 用同一任务邀请 5 位不熟悉扩展规则的用户测试，记录首次成功、卡点和是否需要帮助。尚未进行这项测试，不给出虚构的完成率。
